# Windows 系统级自启动开发任务

[CODEX_LONG_TASK_CONTINUE_V3]

## 任务目标

将当前“用户登录后通过 HKCU Run 启动 Flutter 应用”的机制升级为双进程架构：

- `vnt_service.exe` 作为 Windows 自动启动服务，在无人登录时连接默认 VNT 网络并维护虚拟网卡。
- `vnt_app.exe` 继续作为用户会话中的窗口、托盘和管理界面，通过本机 IPC 管理服务。
- 安装版支持服务安装、升级、恢复和卸载；便携版保留无服务兼容模式。

## 架构约定

### 进程职责

- Windows 服务：VNT 连接、虚拟网卡、自动重连、机器级网络配置、状态 IPC。
- Flutter UI：配置编辑、状态展示、托盘、聊天、远程协助、更新和用户交互。
- `vntcrustdesk`：继续独立负责远程协助，不与 VNT Core Service 合并。

### 存储边界

- 机器级根目录：`%ProgramData%\VNTC APP2.0`。
- 服务配置：`config\service.json`。
- 网络配置：`config\networks.json`。
- 服务状态：`data\service-state.json`。
- 服务日志：`logs\vnt-service.log`。
- 窗口、主题、聊天数据库等用户数据继续保留在用户级存储。

### IPC

- Windows 命名管道：`\\.\pipe\VntCoreService.v1`。
- 协议必须包含版本号、请求 ID、固定命令集合、长度限制和超时。
- 服务端不接受任意命令行、任意文件路径或动态库路径。

## 验收标准

- 冷启动后停留登录界面时，`VntCoreService` 为 `RUNNING`。
- 无用户登录时服务端可见设备在线，其他 VNT 设备可访问其虚拟 IP。
- 用户登录后 GUI 附着服务，不创建第二套虚拟网卡或第二个设备身份。
- 注销用户不影响 VNT 连接。
- 无网络启动、网络恢复、休眠唤醒后可自动重连。
- 服务停止、崩溃恢复、覆盖升级和卸载行为可验证。
- 旧配置迁移后服务器、Token、设备 ID 和默认配置不丢失。
- 普通用户不能用 IPC 令高权限服务执行任意命令或访问任意路径。
- Flutter analyze/test、Rust test、Windows Release 构建通过。
